## 二、创建/编辑脚本页面

### 2.1 基本信息区域

#### 脚本名称 ⭐ 必填
- **说明**: 脚本的唯一标识名称
- **规则**: 
  - 只能包含英文、数字、下划线
  - 建议格式: `项目_功能_类型`
- **示例**: `mysql_stress_test`, `sol_network_config`

#### 测试类型 ⭐ 必填
- **说明**: 脚本的测试类型分类
- **选项**:
  | 类型 | 说明 |
  |------|------|
  | CPU测试 | CPU性能、压力测试 |
  | 内存测试 | 内存性能、稳定性测试 |
  | 磁盘测试 | 磁盘IO、存储测试 |
  | 网络测试 | 网络带宽、延迟测试 |
  | 综合测试 | 多种资源混合测试 |

#### 脚本描述
- **说明**: 脚本功能说明
- **建议**: 描述测试目标、前置条件、预期结果

### 2.3 参数配置区域

#### 添加参数
点击「添加参数」按钮，配置参数信息：

| 字段 | 必填 | 说明 |
|------|:----:|------|
| 参数名 | ✅ | 环境变量名称，脚本中通过此名称获取值 |
| 类型 | ✅ | 参数类型 |
| 默认值 | ❌ | 用户未填写时的默认值 |
| 描述 | ❌ | 参数用途说明 |

#### 参数类型详解

**1. 字符串 (string)**
- 输入: 文本框
- 用途: IP地址、路径、名称等
- 示例: `192.168.1.100`, `/data/test`

**2. 数字 (number)**
- 输入: 数字框
- 用途: 端口、时长、数量等
- 示例: `8080`, `60`, `100`

**3. 布尔 (boolean)**
- 输入: 开关
- 用途: 是否启用某功能
- 值: `true` / `false`

**4. 选择 (select)**
- 输入: 下拉框
- 用途: 固定选项选择
- 配置: 需要定义选项列表

#### 参数命名建议
| 场景 | 命名格式 | 示例 |
|------|---------|------|
| 目标地址 | `TARGET_*` | `TARGET_BMC_IP` |
| 连接信息 | `*_USER`, `*_PASS` | `BMC_USER`, `BMC_PASS` |
| 网络配置 | `NETWORK_*` | `NETWORK_IP`, `NETWORK_GATEWAY` |
| 测试配置 | `TEST_*` | `TEST_DURATION`, `TEST_THREADS` |

### 2.4 执行计划区域

#### 步骤列表
显示所有配置的执行步骤，每个步骤包含以下配置：

#### 步骤配置项

**步骤名称**
- 显示名称，用于任务详情中展示
- 示例: `部署服务`, `执行压测`, `收集结果`

**执行脚本** ⭐ 必填
- 从上传的文件中选择入口脚本
- 只显示 `.sh` 和 `.py` 文件

**依赖步骤**
- 选择需要先完成的步骤
- 支持多选
- 留空表示无依赖，可立即执行

**启动探测**
配置服务就绪检测：

| 类型 | 参数 | 说明 |
|------|------|------|
| TCP | 端口号 | 检测端口是否可连接 |
| HTTP | 端口号 + 路径 | HTTP 请求返回 200 |

**结果解析**
- 启用: 解析此步骤的输出结果
- 解析方式:
  - **内置规则**: 自动识别 Key-Value 或 JSON 格式
  - **自定义脚本**: 使用 Python/Shell 脚本解析

**内置解析格式**

*Key-Value 格式:*
```
total_requests=10000
success_rate=99.5
avg_latency=50
```

*JSON 格式:*
```json
{
  "total_requests": 10000,
  "success_rate": 99.5,
  "avg_latency": 50
}
```

**步骤参数**
- 为该步骤定义专属参数
- 格式与全局参数相同
- 优先级高于全局参数

**本地执行**
- 勾选后脚本在平台服务器本地执行
- 适用场景:
  - SOL 连接目标服务器
  - 本地发起 SSH 连接
  - 使用本地工具（如 ipmitool）

## 三、执行流程说明

### 3.1 步骤执行顺序
```
1. 无依赖步骤并行执行
2. 有依赖步骤等待依赖完成
3. 所有步骤完成后收集结果
```

### 3.2 参数传递
```
全局参数 → 所有步骤可用
步骤参数 → 覆盖全局参数
环境变量 → 脚本中通过 $VAR 或 os.environ 获取
```

### 3.3 本地执行流程
```
平台服务器本地执行脚本
       ↓
脚本解析参数（BMC IP等）
       ↓
连接目标服务器
       ↓
执行测试操作
       ↓
返回执行结果
```

## 四、最佳实践

### 4.1 脚本命名规范
```
项目_功能_类型

示例:
- mysql_stress_test
- sol_network_config
- redis_benchmark
```

### 4.2 参数设计原则
1. **必需参数** - 无默认值，用户必须填写
2. **可选参数** - 有默认值，用户可覆盖
3. **参数分组** - 按功能分组命名

### 4.3 步骤设计建议
1. **单一职责** - 每个步骤只做一件事
2. **明确依赖** - 清晰标注步骤依赖关系
3. **结果解析** - 关键步骤启用结果解析
4. **超时设置** - 合理设置步骤超时时间

### 4.4 错误处理
```bash
# Shell 脚本
set -e  # 遇错退出
trap 'echo "Error at line $LINENO"' ERR

# 输出标准格式
echo "RESULT: key=value"
echo "ERROR: error message"
```

```python
# Python 脚本
import sys
import json

try:
    # 执行逻辑
    result = {"status": "success", "value": 100}
    print(json.dumps(result))
except Exception as e:
    print(json.dumps({"status": "error", "message": str(e)}))
    sys.exit(1)
```

## 五、常见问题

### Q1: 脚本文件太大无法上传？
- 使用压缩包上传
- 分拆为多个小文件

### Q2: 参数如何在脚本中获取？
```bash
# Shell
DURATION=${DURATION:-60}
echo "Duration: $DURATION"
```
```python
# Python
import os
duration = os.environ.get('DURATION', '60')
print(f"Duration: {duration}")
```

### Q3: 步骤之间如何传递数据？
- 通过共享资源文件
- 通过数据库（需自行实现）

### Q4: 本地执行和远程执行的区别？
| 类型 | 执行位置 | 适用场景 |
|------|---------|---------|
| 远程执行 | 目标服务器 | 直接在目标执行命令 |
| 本地执行 | 平台服务器 | 需要本地工具连接目标 |
