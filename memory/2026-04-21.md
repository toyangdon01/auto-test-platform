## SQLite 数据库并发问题

### 问题现象
- Pipeline 执行时取消操作报 `SQLITE_BUSY` 错误
- 数据库连接池耗尽

### 解决方案
1. **增加 HikariCP 连接池配置**
   - `busy_timeout=30000` - SQLite 等待 30 秒
   - `leak-detection-threshold=60000` - 连接泄漏检测
   - `maximum-pool-size=2` - 适合 SQLite

2. **移除取消操作的事务**
   - `PipelineServiceImpl.cancelPipelineRun()` 移除 `@Transactional`
   - 增加重试机制（3 次，每次间隔 1 秒）

3. **待修复** - `TaskServiceImpl.cancelTask()` 仍有 `@Transactional`

### 根本原因
- SQLite 只允许一个写入者
- 多任务并行执行时写入操作排队
- 事务持有锁时间过长导致 SQLITE_BUSY

### 用户偏好
- **修改代码前先分析结论，等确认后再执行**

## WebShell WebSocket 端点修复

### 问题现象
- WebShell 终端连接返回 HTTP 400 错误
- WebSocket 端点未注册

### 问题根因
1. `WebSocketConfig.java` 上有 `@ConditionalOnNotWebApplication` 注解，导致 Web 应用中不加载
2. `WebShellEndpoint.java` 使用独立的 `WebShellConfigurator.class`，但 Spring 容器注入不生效

### 解决方案
1. 移除 `@ConditionalOnNotWebApplication` 注解
2. 使用内嵌的 `SpringConfigurator` 内部类（与 TaskLogEndpoint 一致）
3. 删除独立的 `WebShellConfigurator.java` 文件

### 提交记录
- `0ab06da` - fix: 修复 WebShell WebSocket 端点无法注册的问题
- `f191a4c` - fix: 修复 WebSocket 配置不生效的问题

### 关键代码位置
- `backend/src/main/java/com/autotest/config/WebSocketConfig.java`
- `backend/src/main/java/com/autotest/websocket/WebShellEndpoint.java`

## SSH 连接超时配置修复

### 问题
`session.connect()` 和 `channel.connect()` 调用未使用配置的超时参数

### 解决方案
在 `SshService.java` 中，所有 `session.connect()` 和 `channel.connect()` 调用添加 `defaultTimeout` 参数（共 11 处）

### 配置值
- `autotest.ssh.connect-timeout: 30000` (30 秒)
- `autotest.ssh.exec-timeout: 86400000` (24 小时)

## 测试结果表冗余字段（解除外键依赖）

### 背景
删除任务时会级联删除测试结果，导致历史数据丢失

### 解决方案
在 `test_results` 表添加冗余字段，解除外键依赖：
- `task_name` - 任务名称
- `script_name` - 脚本名称
- `server_name` - 服务器名称
- `server_ip` - 服务器IP

### 数据库变更
```sql
ALTER TABLE test_results ADD COLUMN task_name VARCHAR(255);
ALTER TABLE test_results ADD COLUMN script_name VARCHAR(255);
ALTER TABLE test_results ADD COLUMN server_name VARCHAR(255);
ALTER TABLE test_results ADD COLUMN server_ip VARCHAR(100);
```

### 代码修改
1. `TestResult.java` - 添加冗余字段（从非持久化改为持久化）
2. `TestResultMapper.java` - 移除 JOIN 查询，直接读取冗余字段
3. `TaskExecutionService.java` - 创建结果时填充冗余字段
4. `TestResultServiceImpl.java` - getDetail 直接使用冗余字段
5. `TestResultDetailResponse.java` - 添加 scriptName 字段
6. `schema.sql` - 更新表结构，移除外键约束

### 效果
- 删除任务/服务器不再影响测试结果记录
- 查询性能提升（无需 JOIN）
- 结果记录保留创建时的完整信息

### 注意事项
- 项目未启用 Flyway，需手动执行 SQL
- 后端启动时会自动应用 schema.sql（仅 SQLite 模式）
